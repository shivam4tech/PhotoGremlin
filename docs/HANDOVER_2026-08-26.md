## 1) Build environment — the `pg-env.sh` trap

**Symptom:** `npm run build:app` / `npm run tauri dev` fails with 8 `pkg-config … was not found` errors (`gobject-2.0`, `gdk-pixbuf`, `webkit2gtk`, etc.) and `PKG_CONFIG_PATH environment variable is not set`.

**Root cause:** Tauri's Linux system libs live in a **user-space sysroot** at `~/pgsysroot` (no root on this machine). They are *not* on the system `PKG_CONFIG_PATH`. The file `~/pg-env.sh` exports `PATH`, `PKG_CONFIG_PATH`, `LD_LIBRARY_PATH`, `C_INCLUDE_PATH`. `AGENTS.md` says every cargo/tauri invocation must be `source ~/pg-env.sh && …`.

**Fix:** Always prefix builds:
```bash
source ~/pg-env.sh && npm run build:app
source ~/pg-env.sh && npm run tauri dev
source ~/pg-env.sh && cargo check   # (from src-tauri/)
```

**Handover note:** Do not add `sudo apt install` steps — they will fail (no root). The sysroot is the only supported path.

## 2) Dataset collection — path bugs, licenses, rate limits, dedup

All collection scripts live under `tools/train/dataset/` (stdlib-only, no extra deps) and write under `ml-corpus/` (gitignored: `ml-corpus/`, `tools/train/data/`, `tools/train/runs/` are in `.gitignore`).

### 2.1 `collect_data.py` / `collect_v2.sh` repo-root miscalculation

`collect_data.py` computed `REPO = HERE.parent.parent` where `HERE = tools/train/dataset`. That resolves to `tools/`, not the repo root. Every subprocess then ran with `cwd=tools/`, so all relative `ml-corpus/…` paths were created as `tools/ml-corpus/…`. Symptoms: `skip` logic never triggered on re-run, 7k+ thumbs in the wrong tree, `thumbnails on disk: 65k (6.5 GB)` but `ml-corpus/openimages/images/thumb` still at 39k.

**Fix:** `REPO = HERE.parent.parent.parent` in `collect_data.py`; `cd "$(dirname "$0")/../../.."` in `collect_v2.sh` (the script lives 3 levels deep). Data was relocated with `rm -rf ml-corpus && mv tools/ml-corpus ml-corpus`.

**Same class of bug in `collect_v2.sh`** (initially `cd ../../` instead of `../../../`) → `tools/tools/train/dataset/download_oi_machine.py: No such file`.

### 2.2 Val image CSV moved buckets

`download_metadata.py` fetched `val-images-boxable-with-rotation.csv` from `…/v7/…` → **403 Forbidden**. The val images CSV lives at `2018_04/validation/validation-images-with-rotation.csv` (train at `2018_04/train/…`). The `v7/` path is only for image-level label CSVs. Fixed by pointing val images to `2018_04/validation/`.

Detected via `curl -I`: `v7/` val → 403, `2018_04/train/` → 200.

### 2.3 `License` column is URL-form, not pretty name

`download_images.py` filtered with `KEEP_LICENSES = {"Attribution License"}` and got `0 CC-BY resolvable` of 170k samples. In v7 the CSV `License` column holds URLs like `https://creativecommons.org/licenses/by/2.0/` (or `.../publicdomain/zero/1.0/`), not human labels. Fixed to substring check:
```python
def license_ok(url: str) -> bool:
    return "creativecommons.org/licenses/by/2.0" in url or "publicdomain" in url
```

### 2.4 OI v7 metadata resume was missing

Initial `fetch()` opened `.part` with `wb` always → interrupted 7.3 GB `oidv7-train-annotations-machine-imagelabels.csv` downloads restarted from 0. Patched to resume via `Range: bytes=<existing>-` and `ab` mode. Detached `setsid nohup` jobs still die when the opencode shell session ends — switched to synchronous `python3 …` with a long timeout (the resumable range header makes re-runs cheap).

### 2.5 Machine-label tier: only ~16% of that pool is CC-BY

After selection, `download_oi_machine.py` selected 186k machine-labeled images capped per class, of which only ~29k were CC-BY resolvable. Tier A therefore contributed **~23k** images, not the hoped ~400k. This forced raising Tier B's per-class budget (600 → 1500) and adding Tier B+ (Wikimedia Commons).

### 2.6 `commons_crawl.py` — three bugs in one file

| Bug | Symptom | Fix |
|---|---|---|
| `TypeError: float < None` | `if time.time() < deadline and deadline is not None` evaluated comparison first when `--minutes` omitted (`deadline=None`) | Guard order → `deadline is not None and time.time() > deadline` |

## 3) Training — from single-label ceiling to multi-label, long-tail, and calibration

### 3.1 Single-label assumption capped accuracy

Round-3 single-label model plateaued at ~45% fine top-1. Root cause: Open Images images legitimately carry several scene labels; single-label assignment picks one and penalizes the other.

**Fix:** `select_samples.py --keep-all-labels` writes multi-row CSVs; `train.py --multilabel` uses `MultiLabelDataset` + `BCEWithLogitsLoss` and any-true metrics (`f1 += (top1 ∈ true-set)`). Immediate jump to ~57% fine top-1. `eval_ckpt.py` gained multi-label handling and a merged-taxonomy (10 groups) report.

### 3.2 Canonical label per MID

Three Place365 names mapped to one OI MID (e.g. `church` + `north church` → `01wb7`). Keeping both gave identical images contradictory fine *and* coarse labels.

**Fix:** `map_classes.py` now collapses `by_mid` groups to one canonical label per MID (merged `hospital room→hospital`, `north church→church`, `restaurant patio→restaurant`) → 130 clean fine classes.

### 3.3 Long-tail starvation

`disk_freq` on downloaded thumbs: min 10, median 108, max 5,463. Plain shuffled sampling drowned tail classes.

**Fixes (both in `train.py`):**
- `--sample-power 0.5` soft-balanced sampler: weight `∝ 1/count^0.5` (1.0 = per-class uniform oversamples coarse groups with many tiny classes; 0.5 keeps coarse priors sane)
- `--min-class-train 25` prunes unlearnable micro-tails (16 classes dropped → 114-class head in that run)

### 3.4 `val.csv` schema mismatch crash

Stage-1 with `--corpus ml-corpus/corpus_v2/train.csv` crashed:

```
FileNotFoundError: ...corpus_v2/val.csv...
ValueError: too many values to unpack (expected 4)
```

`build_corpus_v2.py` wrote `val.csv` as a blind `shutil.copyfile(val_multi.csv)` — 5-col schema (`image_id,mid,fine,coarse,confidence`) while `CorpusDataset` expects 4-col corpus schema (`path,fine,confidence,source`). Fixed to convert: `image_id → thumb relative path`, skip missing files, keep multi-label rows, `source=oi_human`.

### 3.5 `export_onnx.py` — external data + int8 collapse

`fp32 exported: 0.4 MB` → torch 2.11 dynamo exporter splits weights to `.onnx.data`; `commit_from_memory`-style loads want one file. Second, int8 static quantization collapsed 0.41→0.21.

**Fix:** fold external data (`convert_model_from_external_data`), any-true dedup-aware accuracy (group rows by path), fall back to shipping **fp32 12.7 MB** when int8 drops >2% (which it did). `calibrate.py` had the same `CORPUS vs samples` val-source bug — fixed to prefer corpus val when present and to initialise `_COARSE_OF_FINE` before constructing `CorpusDataset`.

### 3.6 `eval_ckpt.py` — silent wrong coarse targets

`CorpusDataset` needs `_COARSE_OF_FINE` populated before construction. `train.py:main()` sets it; `eval_ckpt` and `calibrate` imported the class but never set the global → every image got coarse target `other`. Added explicit loading of `class-map.json` into `train_mod._COARSE_OF_FINE` and a loud error in `coarse_of_fine()` when unset.

`POST /v1/auth_tokens/register/` with `{name, description, email}` → returns `client_id/client_secret` plus a **verification email** that must be clicked for higher limits. Then `POST /v1/auth_tokens/token/` with `client_credentials` → bearer token (expires ~12h).

`collect_v2.sh` sources this file if present. Tokens are cached to `ml-corpus/openverse/.token.json` and refreshed on 401/403.

### 5.2 500s and 401/403 self-heal

Openverse threw `HTTP 500` mid-crawl; original `api_get` only retried on 429/502/503 → crash. Patched to retry `500/504` and to treat `401/403` as token-refresh triggers (invalidate cache, refetch).

### 5.3 Wikimedia 429 throttling

Commons thumbnail fetches hit `429: Your bot is making too many requests` (8 aggressive workers). Current `commons_crawl.py` uses 2 workers + per-request pacing with `Retry-After` sleep and exponential backoff (cap 8 s) that decays on successes (`*0.92` toward 0.35 s) plus a liveness line every 250 items. Early single-query validation via `commons_get` confirmed the API shape live.

**What has been fixed already:**

**What is still leaking (user re-confirms):**

Opening a new 200-image folder and clicking "Find similar" still hashes/scans the previous 1000's pending files. The dashboard's `periodStats` and `sessionSummary` are similarly global.

**Next agent's fix (scoped, do not make global → no filter):**
- Add a session-scoped `status_for_session(session_id)` and make `status()` delegate to it when `active_folder` is set, or add a new IPC `project_status` and have `refreshStatus` call it when a project is open.

## 8) Current project — what PhotoGremlin is right now

Privacy-first, local-only desktop catalog for photographers (`PRODUCT_SPEC.md:3`): `import folder → analyze locally → filter by measurable traits → select → rename/move/copy/trash → save view → read statistics`. No account, no cloud, no telemetry — the log at `log_dir/photogremlin.log` is local-only, and the `Privacy contract` in `SettingsView.tsx:291` says so in the UI.

**Core loop (shipped, Sprints 1–10):** `scan` (folder walk, session per root), `thumbnails` (virtualized grid 96/page, `VirtualGrid`), `analysis` (sharpness/brightness/contrast/saturation/clipping/monochrome + EXIF filters), `statistics` (period-scoped), `file-ops` (rename/move/copy/trash with collision handling).

**Local intelligence (Sprints 9, 17–18):** Optional, entirely local, small models embedded in the binary. The whole core works with `ai_enabled=false` or when ONNX Runtime is absent (`ml::runtime_status` → friendly `runtime_note`).

| Scene classification | MobileNetV3-Large two-head (trained on CC-BY Open Images + Commons) | 12.7 MB fp32 | `models/scene_mobilenetv3_large.onnx` |

Scene ships as a stub until export: `tools/train/make_stub_scene_model.py` produces deterministic garbage weights with the real I/O contract; `export_onnx.py` replaces it 1:1 after training.
